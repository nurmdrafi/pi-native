# Specialized subagent archetypes and prompt-design practices

Research brief: which specialized agents and subagent-prompt practices a coding-agent harness should adopt. Primary sources: Anthropic's official Claude Code subagents documentation, Anthropic's multi-agent research-system engineering post, Cognition's "Don't Build Multi-Agents", and the MetaGPT paper. Roster facts (8 agents, frontmatter schema) were taken as given from the task context.

## Answer

Specialization in established multi-agent coding systems follows a stable, small pattern: a recon/explorer, an implementer, a reviewer, and a verifier recur everywhere, with a planner/architect split appearing in systems built around document pipelines. MetaGPT formalizes five roles — Product Manager, Architect, Project Manager, Engineer, QA Engineer — and gets its gains from structured artifacts handed between roles, not from dialogue ([arXiv 2308.00352](https://arxiv.org/abs/2308.00352)). Anthropic's production Research system is an orchestrator-worker pattern where a lead plans and spawns specialized subagents that act as "intelligent filters," doing verbose work in their own context and returning distilled results ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)). Claude Code's own guidance and examples converge on the same archetypes: a read-only code reviewer with Edit/Write excluded and a detailed output-format contract, and a code-improver that scans after code is written ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)). This harness's roster (scout, worker, reviewer, verifier, ui-verifier, docs-optimizer, researcher, bench-runner) already covers the recurring core almost exactly — the gap is not missing archetypes but under-specified contracts on the existing ones.

The evidence says specialization pays for breadth-first, parallelizable, self-contained work, and hurts for tasks whose parts share hidden assumptions. Anthropic reports multi-agent (Opus lead, Sonnet subagents) beating single-agent Opus by 90.2% on breadth-first research evals, and finds token usage alone explains 80% of performance variance — the architecture is largely a mechanism for spending enough tokens across separate context windows ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)). Claude Code's docs give the routing rule: use the main conversation when work needs frequent back-and-forth, shared context across phases, or low latency; use a subagent when output is verbose, tools must be restricted, or the work is self-contained and returns a summary ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)). Cognition gives the counterweight: parallel subagents making independent decisions on one task produce conflicting outputs (their Flappy Bird example: two subagents ship mismatched visual styles), so their principles are "share context — full traces, not individual messages" and "actions carry implicit decisions"; their default is a single-threaded linear agent, with multi-agent reserved for tasks that overflow context ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)). For this roster that argues against splitting one cohesive change across a writer and a separate refactor/migration agent, and for the existing rule of baking verified facts into child prompts before spawning.

On prompt design, three practices are documented at the sources. First, routing is driven by the description field: each must uniquely identify when to delegate, and combined descriptions should stay well under a 15,000-token budget, with detail pushed into the per-agent system prompt that only loads when that agent runs ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)). Second, subagent prompts work best as collaboration frameworks that define division of labor, explicit task descriptions, output formats, and effort budgets — Anthropic embeds literal scaling rules (simple fact-finding: 1 agent, 3–10 tool calls; comparisons: 2–4 subagents, 10–15 calls each; complex: 10+ with divided responsibilities) because agents otherwise over- or under-invest ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)). Third, subagent results should be persisted as filesystem artifacts with only lightweight references passed back — this prevents the "game of telephone" and token bloat from copying large outputs through conversation history ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)); MetaGPT's artifact-passing assembly line is the same idea ([arXiv 2308.00352](https://arxiv.org/abs/2308.00352)). This harness's durability-file pattern is independently validated by both.

Net recommendation: tighten the existing eight (effort budgets, tool-ban lists, output-format contracts, description-as-router discipline) rather than grow the roster; add at most a focused read-only security reviewer (strong pattern fit, cheap, isolates a high-stakes concern) and consider a planner for large multi-wave features (MetaGPT-backed), while rejecting test-writer and refactor/migration agents as worker duplicates that Cognition's evidence warns against.

## Key Findings

- Recurring roles in multi-agent coding systems: MetaGPT defines five — Product Manager, Architect, Project Manager, Engineer, QA Engineer — each with profile, goal, constraints, skills; work flows as an assembly line of structured artifacts (PRD → system design → code), not dialogue ([arXiv 2308.00352](https://arxiv.org/abs/2308.00352)).
- Anthropic's production Research system uses an orchestrator-worker pattern: lead agent analyzes, plans, spawns parallel specialized subagents that act as intelligent filters and return distilled results ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- Claude Code's official example subagents are exactly a focused archetype pair: a read-only code reviewer (no Edit/Write, detailed prompt specifying what to look for and how to format output) and a code-improver (scan files after modification, suggest readability/performance/best-practice improvements) ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)).
- Subagents should each excel at one specific task; descriptions must be distinct enough to route correctly, and when combined non-built-in descriptions exceed 15,000 tokens Claude Code warns — trim descriptions and move detail into the system prompt that loads only on run ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)).
- Limit tool access to only what is necessary "for security and focus"; share subagents via version control ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)).
- Use the main conversation when work needs frequent back-and-forth, shared context across phases (planning + implementation + testing), a quick targeted change, or low latency; use a subagent for verbose output, tool restriction, or self-contained work returning a summary; subagent requests count against the same usage limits ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)).
- Multi-agent beats single-agent on breadth-first parallel queries: Opus lead + Sonnet subagents outperformed single-agent Opus by 90.2% on Anthropic's internal research eval; a single agent failed sequential board-member lookups where decomposition succeeded ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- Token usage alone explains 80% of performance variance on BrowseComp (three factors explain 95%); multi-agent architecture is fundamentally a way to scale token spend past single-agent limits — model upgrades beat token-budget doubling ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- Agents cannot judge appropriate effort unaided: early failures included "spawning 50 subagents for simple queries" and endless searches; the fix was embedding scaling rules in prompts (1 agent / 3–10 calls; 2–4 subagents / 10–15 calls; 10+ subagents for complex research) ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- Subagent outputs should go to the filesystem with lightweight references passed back, not be copied through the coordinator — prevents information loss ("game of telephone") and token overhead; best for structured outputs like code, reports, data ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- The best multi-agent prompts are "frameworks for collaboration" defining division of labor, problem-solving approach, and effort budgets; small changes to the lead agent unpredictably change subagent behavior (emergent interaction) ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- Cognition's principles: (1) share context, and share full agent traces, not individual messages; (2) actions carry implicit decisions, and conflicting decisions carry bad results — parallel subagents on one task ship inconsistent work (Flappy Bird: Super Mario background vs a different game's bird) ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)).
- Cognition's default is a single-threaded linear agent; they advise ruling out architectures that violate the two principles, using multi-agent only where large tasks overflow context windows ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)).
- Model tiering for simple subagent jobs is standard practice (Anthropic assigns cheaper/faster models to subagents doing simple jobs) ([Claude Code best practices](https://www.anthropic.com/engineering/claude-code-best-practices)).

## Recommendations for this roster

### (a) Improvements to existing agents

- `agents/scout.md` — Read-only contract is not enforced by its toolset (pibash can write). Add an explicit ban list with failure reasons ("no file writes, no installs, no git state changes — report if needed") to the body; tool-scoping for focus and security is the documented reason to use subagents at all ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)). Also add an effort budget per task size (e.g. "recon: ≤N tool calls unless told otherwise") — agents left to judge effort overinvest ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- `agents/worker.md` — Add "teach the spawn" discipline to the body: every child prompt must carry an explicit output format, expected call-count budget, and the facts the child needs, because children cannot see the worker's context and conflicting implicit decisions produce inconsistent work ([Cognition](https://cognition.ai/blog/dont-build-multi-agents), [Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)). Codify the inline-vs-spawn routing rule already in global instructions (back-and-forth or shared-context work stays inline) as the file's own gate ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)).
- `agents/reviewer.md` — Confirm and document the read-only toolset (Edit/Write excluded) and the exact output format (what to check: correctness, races, guard regressions; how to report); this mirrors the official code-reviewer example where the detailed prompt specifies "exactly what to look for and how to format output" ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)).
- `agents/verifier.md` and `agents/ui-verifier.md` — Route full result tables through the durability file and return only a summary plus reference, the documented pattern for structured outputs ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)); add sweep-size effort budgets to ui-verifier ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- `agents/researcher.md` — Encode effort tiers in the body (simple: 1–2 searches/few calls; comparison: 2–3 angles; deep: extract-first workflow), mirroring Anthropic's literal scaling rules ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)).
- All agents — Treat the `description` field as the router: keep each short, distinct, and stating when to use this agent versus worker; combined descriptions must stay far below the 15K-token guidance, with detail living in the body that loads only on run ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)). Keep agent files in version control as shared team assets ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)).

### (b) Candidate NEW agents (ranked by expected value)

1. **security-reviewer** — Role: read-only pass over diffs touching trust boundaries (auth, input validation, secrets, injection, data-loss paths). Tools: `ls, piread, pibash` (read-only ban list in body). Thinking: high. Spawn: before commit when a diff crosses a trust boundary or handles secrets/permissions; otherwise stay with reviewer. Evidence: the documented focused-reviewer archetype — one concern, restricted tools, explicit checklist and output format ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)) — and specialization's value for self-contained, restricted-tool work ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)). No duplication: reviewer checks correctness broadly; this is a distinct, higher-stakes contract. Highest expected value: cheap, isolated, and its concern is explicitly never-cut territory in this harness.
2. **planner** (architect) — Role: draft multi-file design/implementation plans (interfaces, file lists, data structures, wave sequencing) handed to worker as an artifact. Tools: `ls, piread, pibash` (read-only). Thinking: high. Spawn: for large features needing a written plan before waves; not for quick changes or work already planned in-session (Cognition: splitting shared-context phases across agents loses context; Claude Code docs: keep planning and implementation in one context when they share it). Evidence: MetaGPT's Architect role producing system design (file lists, data structures, interface definitions) as an assembly-line artifact ([arXiv 2308.00352](https://arxiv.org/abs/2308.00352)); orchestrator-worker split ([Anthropic engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)). Flag: partially duplicates the main agent's plan-first rule — worth adding only if large pre-planned features recur.
3. **triage** — Role: classify a failure (environmental vs code, reproducible vs flaky) and hand worker a scoped issue with facts baked in. Tools: `ls, piread, pibash`. Thinking: medium. Spawn: on repeated CI/test failure of unknown cause. Evidence: weak/indirect — Cognition's share-context principle supports it only as a fact-gathering front end whose full trace informs the fixer ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)); no primary source documents a triage archetype. Flag: near-duplicate of scout — prefer extending `agents/scout.md` with a triage contract over a new file.
4. Rejected: **test-writer** and **refactor/migration** agents — duplicate worker. TDD is already the global workflow, and Cognition's evidence directly warns that parallel implementers with separate contexts on one cohesive task ship inconsistent work ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)); Claude Code's routing rule keeps tightly coupled phases in one context ([Claude Code docs](https://code.claude.com/docs/en/sub-agents)). Handle both as worker briefs/skills, not agents. **release/shipping** and **data/SQL** agents: no primary-source evidence found either way — do not add on current evidence.

## Confidence & Gaps

Solid: role taxonomy (MetaGPT five roles, orchestrator-worker), the specialization tradeoff evidence (90.2% breadth-first win, token-variance finding, effort-scaling rules, filesystem-artifact pattern from Anthropic; conflicting-decisions critique from Cognition), and the Claude Code description-budget and tool-scoping practices — all read from primary pages. Medium: the security-reviewer and planner recommendations are applications of documented patterns, not documented archetypes in a coding harness; expected value is reasoning, not measurement. Gaps: MetaGPT details come from the paper's abstract/summary snippets (roles, artifact flow) rather than full-text extraction; no primary evidence found for release/shipping, triage, or data-analyst archetypes in coding systems; no quantitative study of description-length vs routing accuracy beyond the 15K-token warning threshold; and all performance numbers are Anthropic-internal evals on research tasks, not coding tasks — transfer to this harness is plausible but unverified.
